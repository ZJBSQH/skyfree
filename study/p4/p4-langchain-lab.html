LLM 封装 — ChatOpenAI 对接 Ollama

核心

概念 是什么

LangChain 用 ChatOpenAI 类统一封装所有兼容 OpenAI 协议的 LLM。不管你后端跑的是 Ollama、DeepSeek 还是通义千问，只要提供兼容的 base_url + api_key，调用方式完全一致。

对比 P3：P3 用 openai.OpenAI() 直调，每次要手动构造 messages 数组、处理异常。ChatOpenAI 帮你处理了重试、超时、token 计数等通用逻辑。

代码示例 怎么写

# P3 方式 (raw SDK)
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
response = client.chat.completions.create(
    model="qwen2.5:3b",
    messages=[{"role": "user", "content": "你好"}]
)
print(response.choices[0].message.content)

# P4 方式 (LangChain 封装)
from langchain.chat_models import init_chat_model
llm = init_chat_model(
    model="qwen2.5:3b",
    model_provider="openai",          # 使用 OpenAI 兼容协议
    base_url="http://localhost:11434/v1",
    api_key="ollama"
)
response = llm.invoke("你好")          # 直接传字符串，更简洁
print(response.content)
⚠ 关键理解：model_provider="openai" 不是说必须用 OpenAI 的模型，而是告诉 LangChain 使用 OpenAI 兼容的 API 协议——Ollama、DeepSeek、vLLM 都兼容这个协议。

Prompt Template — 动态构建提示词

核心

概念 是什么

P3 中我们用 f-string 拼 prompt，变量一多就容易乱。LangChain 的 ChatPromptTemplate 让你用模板语法分离"结构"和"数据"：

  • {variable} — 普通占位符，替换文本
  • MessagesPlaceholder — 给对话历史留位置，LangChain 自动拼接
  • SystemMessagePromptTemplate / HumanMessagePromptTemplate — 区分不同 role 的模板

代码示例 怎么写

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

# 定义模板：分离结构
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一位{role}，擅长{skill}。文风：{style}。"),
    MessagesPlaceholder(variable_name="history"),  # 对话历史自动拼接
    ("human", "{user_input}")
])

# 填充变量：注入数据
filled = prompt.invoke({
    "role": "大纲设计师",
    "skill": "玄幻小说大纲",
    "style": "简洁有力",
    "history": [],                         # MessagesPlaceholder 会在运行时填充
    "user_input": "一本穿越修真界的小说"
})
# filled 现在是标准的 ChatPromptValue，可直接喂给 LLM

LCEL Chain — 管道式组合

核心

概念 是什么

LCEL (LangChain Expression Language) 用 | 管道符像搭积木一样串联组件。每个组件的输出自动成为下一个组件的输入。

代码示例 怎么写

from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = init_chat_model("qwen2.5:3b", model_provider="openai",
                      base_url="http://localhost:11434/v1", api_key="ollama")

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是大纲设计师，生成{num}章大纲。"),
    ("human", "灵感：{idea}")
])

# LCEL 管道链：数据像水流一样从左到右
chain = prompt | llm | StrOutputParser()

# 一行调用，整个流程自动执行
result = chain.invoke({"num": 10, "idea": "穿越修真界"})
print(result)  # 纯字符串输出

LCEL vs Raw SDK 对比

维度P3 raw openai SDKP4 LCEL Chain
代码量每次手动构造 messages dict模板+管道，一行 invoke
组件替换改 model 要改多处换 llm 参数即可，链不变
流式输出stream=True + 手动迭代chain.stream() 一行搞定
异步支持需用 async clientchain.ainvoke() 原生 async
可观测性无内置LangSmith 自动追踪每一步

Output Parser — 结构化输出

核心

概念 是什么

LLM 返回的是自然语言文本，但代码需要结构化数据。Output Parser 把 LLM 的输出解析成 Python 对象。

Parser输入输出
StrOutputParserAIMessage 对象纯字符串 str
PydanticOutputParserJSON 文本Pydantic 对象（带校验）
JsonOutputParserJSON 文本dict
⚠ 考试踩坑提醒：StrOutputParser 的作用是把 AIMessage 对象提取为纯字符串，不是把输入解析成 Prompt 变量。这是考试单选题 Q6 的知识点。

代码示例 — PydanticOutputParser 怎么写

from pydantic import BaseModel, Field
from langchain_core.output_parsers import PydanticOutputParser

# 1. 定义期望的输出结构
class ChapterOutline(BaseModel):
    title: str = Field(description="章节标题")
    summary: str = Field(description="章节摘要，50字以内")
    key_events: list[str] = Field(description="关键事件列表")

parser = PydanticOutputParser(pydantic_object=ChapterOutline)

# 2. 把格式要求注入 prompt
prompt = ChatPromptTemplate.from_messages([
    ("system", "生成一章大纲。\n{format_instructions}"),
    ("human", "章节号：{ch}")
])
prompt = prompt.partial(format_instructions=parser.get_format_instructions())

# 3. LCEL 管道
chain = prompt | llm | parser       # 输出是 ChapterOutline 对象！

obj = chain.invoke({"ch": 1})
print(obj.title)      # 直接用 . 访问字段，带类型提示
print(obj.summary)
print(obj.key_events)

Memory — 对话记忆

核心

概念 是什么

LLM 本身是无状态的——每次调用都是"新对话"。Memory 组件负责存储和注入对话历史，让 LLM 能"记住"之前聊过什么。

关键组件：
InMemoryChatMessageHistory → 内存存储，重启即丢（开发/测试用）
RunnableWithMessageHistory → 包装 chain，自动管理历史存取
session_id → 区分不同用户/会话的关键标识
⚠ 考试踩坑提醒：InMemoryChatMessageHistory 存在内存中，服务重启后历史消失。生产环境需要用 Redis/数据库实现持久化。这是判断题Q5的考点。

代码示例 怎么写

from langchain_community.chat_message_histories import ChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

# 1. 内存存储（字典，key=session_id）
store = {}

def get_session_history(session_id: str):
    if session_id not in store:
        store[session_id] = ChatMessageHistory()
    return store[session_id]

# 2. 用 RunnableWithMessageHistory 包装已有 chain
chain_with_memory = RunnableWithMessageHistory(
    chain,                    # 前面 LCEL 定义的 chain
    get_session_history,      # 获取历史的回调函数
    input_messages_key="user_input",   # 哪个变量是用户输入
    history_messages_key="history",    # 哪个变量接收历史消息
)

# 3. 调用时传入 session_id
config = {"configurable": {"session_id": "user-001"}}
result1 = chain_with_memory.invoke(
    {"user_input": "我叫郑"}, config=config
)
result2 = chain_with_memory.invoke(
    {"user_input": "我叫什么？"}, config=config
)
# result2 会回答"郑"，因为历史中有之前的对话
session_id 的作用：同一个 session_id 共享一段历史。你在浏览器 A 和浏览器 B 分别传不同 session_id，它们的对话完全隔离。

Agent + Tools — 智能体+工具调用

核心

概念 是什么

Chain 走固定路径，Agent 自己决定调用哪个工具、什么顺序、调几次。

  • Tool：一个可被 Agent 调用的函数，用 @tool 装饰器定义
  • Agent：接收用户输入 → 思考 → 决定调哪个 Tool → 拿到结果 → 继续思考/输出答案
  • AgentExecutor：管理 Agent 的思考-行动循环 (ReAct Loop)

代码示例 怎么写

from langchain_core.tools import tool
from langchain.agents import create_tool_calling_agent, AgentExecutor

# 1. 定义自定义工具
@tool
def get_word_count(text: str) -> int:
    """统计文本的字数。"""
    return len(text)

@tool
def save_chapter(chapter_num: int, content: str) -> str:
    """保存章节到文件。chapter_num 是章节号，content 是正文。"""
    filename = f"chapter_{chapter_num}.txt"
    with open(filename, "w", encoding="utf-8") as f:
        f.write(content)
    return f"已保存 {len(content)} 字到 {filename}"

tools = [get_word_count, save_chapter]

# 2. 创建 Agent
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是写作助手。可以用工具统计字数、保存章节。"),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])
agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# 3. 调用：Agent 自己决定调不调工具、调哪个
result = executor.invoke({
    "input": "写一段300字的开场白，统计字数后保存为第1章"
})

Stream — 流式输出

核心

概念 是什么

非流式：等 LLM 全部生成完 → 一次性返回（用户干等）
流式：LLM 每生成一个 token 就推送（ChatGPT 那样逐字出现）

P3 用 stream=True + 手动迭代，P4 用 chain.stream() 一行搞定。

代码示例 怎么写

# P3 流式 (raw SDK)
stream = client.chat.completions.create(
    model="qwen2.5:3b", messages=[...], stream=True
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

# P4 流式 (LCEL) —— 简单得多
for chunk in chain.stream({"idea": "穿越修真界"}):
    print(chunk, end="")     # chunk 已经是解析后的字符串
