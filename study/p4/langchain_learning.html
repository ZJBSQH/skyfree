01 / MAP

先看全图

P3 里你手动控制请求和响应。P4 用 LangChain 把这些重复工作封装成可组合的组件。

Prompt→Model→Parser→业务结果
用户问题→Agent→Tool→最终回答
记忆点：Chain 是固定流水线；Agent 是可以根据问题决定下一步动作的执行者。先学 Chain，再学 Agent，思路会稳很多。
02 / MODEL

模型封装

`init_chat_model` 负责把“模型是谁、从哪里访问、用什么参数”集中配置起来。

核心代码
from langchain.chat_models import init_chat_model

model = init_chat_model(
    model="qwen2.5:3b",
    model_provider="openai",
    base_url="http://localhost:11434/v1",
    api_key="ollama",
    temperature=0.7,
)

response = model.invoke("你好")
print(response.content)
你要掌握

invoke：一次性调用，返回一个消息对象。

content：消息中的文本内容。

temperature：控制输出的随机程度。

03 / PROMPT

Prompt Template

不要每次手写整段 prompt。模板把固定角色和变化输入分开，让链条可以反复使用。

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一位{role}，擅长{skill}。"),
    ("human", "{user_input}"),
])

messages = prompt.invoke({
    "role": "大纲设计师",
    "skill": "设计有悬念的故事大纲",
    "user_input": "主角穿越到修真世界",
})
练习

把角色改成“人物设定师”，增加一个 `{genre}` 变量，要求模型输出人物目标、弱点和秘密。

模板的价值是可复用。以后主编、人物、世界观 Agent 都可以拥有自己的模板。
04 / LCEL

把组件接成 Chain

LCEL 用 `|` 表达数据流：前一个组件的输出，成为后一个组件的输入。

from langchain_core.output_parsers import StrOutputParser

chain = prompt | model | StrOutputParser()

result = chain.invoke({
    "role": "大纲设计师",
    "skill": "设计有悬念的故事大纲",
    "user_input": "主角穿越到修真世界",
})

print(result)  # 直接得到字符串
P3：手动处理response.choices[0].message.content
P4：组合处理prompt | model | parser
05 / MEMORY

给对话加记忆

模型本身不会自动记住上一次对话。Memory 的本质是：在每次调用前，把历史消息重新放回上下文。

from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

store = {}

def get_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

conversation = RunnableWithMessageHistory(chain, get_history)

conversation.invoke(
    {"role": "主编", "skill": "玄幻小说", "user_input": "记住我喜欢快节奏"},
    config={"configurable": {"session_id": "demo-1"}},
)
重要边界

session_id 决定使用哪一段对话历史。

InMemory 只适合学习和单进程测试，重启后会丢失。

未来接 Java 时，业务数据仍由 Java 管，Python 只负责 Agent 编排。

06 / TOOL

工具与 Agent

Tool 是 Agent 可以调用的明确动作。它应该查询或执行一件具体的事，不应该把所有推理都藏进去。

工具
from langchain.tools import tool

@tool
def get_current_chapter(chapter_num: int) -> str:
    """查询已写章节的摘要"""
    return f"第{chapter_num}章摘要：..."
Agent
from langchain.agents import create_agent

agent = create_agent(
    model=model,
    tools=[get_current_chapter],
    system_prompt="你是小说主编，需要时查询章节摘要。",
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "写第5章"}]
})
适合做 Tool查询章节摘要、查询人物状态、统计已完成章节、保存用户确认结果。
不适合做 Tool把主 Agent 的全部 prompt 和整个创作流程再次塞进一个函数。
07 / STREAM

流式输出

流式输出不是让模型变聪明，而是让用户更早看到结果。它会成为后续 Java → Python → 前端 SSE 的基础。

for chunk in chain.stream({
    "role": "大纲设计师",
    "skill": "设计有悬念的故事大纲",
    "user_input": "主角获得仇恨值面板",
}):
    print(chunk, end="", flush=True)
当前目标：先在终端看到逐段输出。等 P5 的 Agent 流程稳定，再把输出封装成 SSE，不要同时引入太多变量。

动手作业 / P4 完成标准

完成一个带偏好的大纲 Agent

  1. 创建一个 `ChatPromptTemplate`，至少包含角色、写作风格和用户灵感三个变量。
  2. 使用 `prompt | model | StrOutputParser()` 创建 Chain，先实现非流式调用。
  3. 增加 `session_id` 记忆：用户第一次说“我喜欢快节奏”，第二次只输入灵感，模型仍能遵守偏好。
  4. 定义一个 `@tool`，用于查询某一章的摘要。工具返回固定假数据即可。
  5. 使用 Agent 判断什么时候调用工具，并保存一份运行截图或终端输出。
  6. 最后实现 `chain.stream()`，观察输出是否逐段出现。
