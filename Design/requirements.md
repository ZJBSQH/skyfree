# Freesky 需求分析文档

> 多Agent创意写作助手 — 需求分析与系统设计

---

## 一、项目概述

### 1.1 项目背景

写作者在创作长篇小说时面临多个挑战：灵感碎片难以组织、大纲结构设计复杂、人物塑造需要一致性、写作效率低下。传统 AI 写作工具多为"单次对话"，无法支撑长篇创作的完整流程。

本系统通过**多 Agent 协作**模式，将写作流程拆解为：灵感收集 → 蓝图构思（大纲/人物/世界观）→ 逐章创作 → 润色定稿，每个环节由专业 Agent 负责，用户全程可控。

### 1.2 核心用户

**写作者** — 网文作者、小说创作者。多用户平台，每位用户拥有独立工作空间。

### 1.3 核心场景

| 场景 | 描述 |
|------|------|
| 从零创作 | 用户输入一句话灵感 → 系统展开为完整作品 |
| 导入续写 | 用户导入已有草稿 → 系统在此基础上续写/优化 |

## 二、功能模块

### 2.1 灵感模块

收集和管理灵感碎片。灵感可以独立存在，也可以关联到一个或多个创作项目（N:M）。

**核心功能**：
- 灵感 CRUD（标题、内容、分类标签）
- 灵感 → 展开为创作项目
- 灵感与项目关联管理

### 2.2 构思模块（创作蓝图）

以**大纲为核心**的创作前期策划。大纲为自引用树结构（卷 → 章），人物和世界观独立管理但关联到具体章节。

**核心功能**：
- 大纲生成（卷/章树结构）
- 人物设计（名称、角色类型、外貌/性格/背景描述）
- 世界观设计（修炼体系/势力/地理等分类）
- 人物-章节关联（角色在哪章出场）
- 世界观-章节关联（设定在哪章揭示）

### 2.3 创作模块

基于蓝图逐章写作。用户确认蓝图后，Agent 按顺序生成每章正文。

**核心功能**：
- 逐章生成（一章完成 → 用户确认 → 下一章）
- 手动编辑正文
- 对话式重写（告诉 Agent 哪里不满意，重新生成）
- Agent 自动记住前文人物状态和伏笔

### 2.4 Skill 模块

写作风格模板库。创作 Agent 在写作时从中选择对应风格。

**核心功能**：
- 风格模板 CRUD（名称、类型、Prompt 模板）
- 系统预设 + 用户自定义
- 项目关联风格（一个项目使用一种风格）

## 三、多Agent协作流程

### 3.1 Agent 角色

```
主编Agent (Orchestrator)
  ├── 大纲Agent     — 根据灵感生成章节大纲
  ├── 人物Agent     — 设计人物档案
  ├── 世界观Agent   — 构建世界观设定
  └── 写稿Agent     — 逐章写作，引用前文上下文
```

### 3.2 写作流程（逐步交互模式）

```
用户输入灵感
  │
  ▼
主编Agent 接收 → 规划任务
  │
  ▼
大纲Agent 生成大纲 → 用户审核确认
  │
  ▼
人物Agent 设计角色 → 用户审核确认
  │
  ▼
世界观Agent 构建设定 → 用户审核确认
  │
  ▼
写稿Agent 逐章写作 ← 用户每章审核
  │
用户确认继续 → 写下一章
用户不满意 → 对话式重写 → 再确认
```

### 3.3 交互细节

- **修改方式**：手动编辑 + 对话式让 Agent 重写，两者均支持
- **上下文管理**：Agent 写第N章时，能看到前面章节的人物状态和伏笔
- **风格切换**：创作时可选用不同 Skill 模板

## 四、数据库设计

共 10 张表，详见 `er-diagram.drawio`（可用 draw.io 打开）。

| 表 | 说明 | 行数预估 |
|----|------|---------|
| user | 用户表 | 1000 |
| inspiration | 灵感表 | 10000 |
| project | 创作项目表 | 1000 |
| project_inspiration | 灵感-项目关联 (N:M) | 5000 |
| chapter | 章节表（自引用树） | 100000 |
| person | 人物表 | 5000 |
| person_chapter | 人物-章节关联 (N:M) | 50000 |
| world_setting | 世界观表 | 3000 |
| world_setting_chapter | 世界观-章节关联 (N:M) | 30000 |
| skill | 写作风格模板 | 100 |

### 核心关系

```
user ──1:N──→ inspiration
user ──1:N──→ project
user ──1:N──→ skill
project ──N:1──→ skill (选用风格)
project ──N:M──→ inspiration
project ──1:N──→ chapter (自引用: parent_id → id)
project ──1:N──→ person ──N:M──→ chapter
project ──1:N──→ world_setting ──N:M──→ chapter
```

## 五、技术架构

### 5.1 系统边界

```
前端 (uni-app / Vue 3)
  │
  ▼ HTTP REST
Java 后端 (Spring Boot)
  ├── 用户模块 (注册/登录)
  ├── 项目管理 (小说 CRUD)
  ├── 灵感模块 (CRUD + 关联)
  ├── Skill 模块 (模板管理)
  └── Agent 调用层 (封装对 Python 的 HTTP → SSE)
  │
  ▼ HTTP (内部)
Python Agent 服务 (FastAPI)
  ├── 主编 Agent (Orchestrator)
  ├── 大纲/人物/世界观/写稿 Agent (Workers)
  └── LLM 适配层 (openai SDK → DeepSeek/通义千问)
```

### 5.2 技术边界

| 放在 Java | 放在 Python |
|-----------|-------------|
| 用户注册/登录 | Agent 编排 |
| 项目管理 CRUD | LLM 调用 |
| API Key 管理（加密存储） | Prompt 模板管理 |
| 灵感/Skill CRUD | SSE 流式输出 |
| 文件导出 (PDF/EPUB) | — |

### 5.3 Agent 框架路线

```
Phase A（当前）: 自建轻量框架
  └── openai SDK 直调 DeepSeek，理解 Agent 本质

Phase B: LangGraph
  └── 状态图编排，"逐步交互"天然匹配

Phase C: 多模型切换 + 生产优化
```
